## 這一批要遵守的既有設計決定

**編輯層自己畫 SVG，預覽用真正的 WaveDrom 引擎。**

理由：官方引擎輸出的 DOM 沒有穩定契約。fork 的 CONTRACT.md 記錄了同一個發現，
並舉出 vditor 為了取到波形矩形而寫出 `[id^='waves_'] > rect` 這種選擇器當證據。
在 md2doc 這個理由同樣成立，而且更強——md2doc pin 在 `wavedrom@3.5.0`
（`lib/md2doc.js` 的註解寫明：3.6.1+ 的 `exports` map 不再暴露
`wavedrom/wavedrom.min.js` 與 `wavedrom/skins/default.js`），任何依賴引擎 DOM 形狀的
互動都會在升版時無聲壞掉。

**overlay 掛在 `document.body`，不掛在 block 裡。**

塞進 `.content` 內的 DOM 會被序列化進 markdown。這是 md2doc 編輯器既有的硬約束。

**Escape 的語意與 v3.3.0 的其餘部分一致**：丟棄，但可以用 `Ctrl+Z` 取回。
不得產生一個「丟了就沒了」的新入口。

## Task 1: WaveJSON 解析器（帶位元組區間）

**Files:**
- Create: `lib/editor/wave-codec.js`
- Create: `test/wave-codec.test.js`
- Modify: `package.json`

**Interfaces:**
- Produces:
  - `parseSource(text) -> { doc, spans, ok: true } | { ok: false, message, offset }`
  - `doc` 是普通 JS 物件（`{ signal: [...], head, foot, config }`）
  - `spans` 把每個值的路徑對應到它在 `text` 裡的 `[start, end)`，路徑用陣列表示，例如 `['signal', 0, 'wave']`

### 為什麼不能用 `JSON.parse`

WaveJSON **是 JS 物件字面值，不是嚴格 JSON**。真實世界的 wavedrom code block
幾乎都長這樣：

```
{ signal: [
  { name: "clk",  wave: "p......" },   // 主時脈
  { name: "data", wave: "x.34.5x", data: ["a","b","c"] },
]}
```

鍵不加引號、有尾逗號、有行內註解——`JSON.parse` 三樣都拒絕。

而且**最小 patch 寫回需要位元組區間**：改一個 cycle 只能動 `wave` 那個字串字面值
所在的那幾個位元組，其餘（包含那句 `// 主時脈`）逐字不動。所以解析器必須一邊解析
一邊記錄每個值的來源區間。

- [ ] **Step 1: 寫會紅的測試**

`test/wave-codec.test.js`（骨架抄 `test/blockmap.test.js`）：

```js
const assert = require('assert');
const C = require('../lib/editor/wave-codec.js');

const SRC = [
  '{ signal: [',
  '  { name: "clk",  wave: "p......" },   // 主時脈',
  "  { name: 'data', wave: 'x.34.5x', data: ['a','b','c'] },",
  ']}',
].join('\n');

// 解析
{
  const r = C.parseSource(SRC);
  assert.strictEqual(r.ok, true, '寬鬆語法必須解析得出來。Got ' + JSON.stringify(r));
  assert.strictEqual(r.doc.signal.length, 2);
  assert.strictEqual(r.doc.signal[0].name, 'clk');
  assert.strictEqual(r.doc.signal[0].wave, 'p......');
  assert.strictEqual(r.doc.signal[1].name, 'data', '單引號字串');
  assert.deepStrictEqual(r.doc.signal[1].data, ['a', 'b', 'c']);
}

// 尾逗號
assert.strictEqual(C.parseSource('{ signal: [ {name:"a",wave:"01"}, ] }').ok, true,
  '尾逗號必須被接受');

// 區塊註解
assert.strictEqual(C.parseSource('{ /* hi */ signal: [] }').ok, true,
  '區塊註解必須被接受');

// 區間
{
  const r = C.parseSource(SRC);
  const span = r.spans.get(JSON.stringify(['signal', 0, 'wave']));
  assert.ok(span, "spans 必須含 ['signal',0,'wave']");
  assert.strictEqual(SRC.slice(span[0], span[1]), '"p......"',
    '區間必須框住整個字串字面值（含引號）。Got ' +
    JSON.stringify(SRC.slice(span[0], span[1])));
}

// 壞掉的來源：回報而不是丟例外
{
  const r = C.parseSource('{ signal: [ {name: } ] }');
  assert.strictEqual(r.ok, false, '壞掉的來源不得回 ok');
  assert.strictEqual(typeof r.offset, 'number', '必須指出位置');
  assert.ok(r.message, '必須有訊息');
}

console.log('wave-codec.test.js OK');
```

## Task 2: 最小 patch 寫回

**Files:**
- Modify: `lib/editor/wave-codec.js`
- Modify: `test/wave-codec.test.js`

**Interfaces:**
- Consumes: Task 1 的 `parseSource()`
- Produces:
  - `patchSource(text, parsed, edits) -> { text, ok: true } | { ok: false, reason, rewroteRange }`
  - `edits` 是 `[{ path: ['signal',0,'wave'], value: 'p...x..' }, ...]`
  - 無法只做局部替換時 `ok: false` 並在 `rewroteRange` 說明它想動哪一段

- [ ] **Step 1: 寫會紅的測試**

```js
// 最小 patch：只有目標區間變，其餘逐字不動
{
  const r = C.parseSource(SRC);
  const out = C.patchSource(SRC, r, [{ path: ['signal', 0, 'wave'], value: 'p..x...' }]);
  assert.strictEqual(out.ok, true);
  assert.ok(out.text.includes('// 主時脈'), '註解必須原樣留著');
  assert.ok(out.text.includes("'data'"), '單引號風格必須原樣留著');
  assert.ok(out.text.includes('wave: "p..x..."'),
    '目標必須被換掉，而且沿用原本的雙引號。Got ' + JSON.stringify(out.text));

  // 逐字比對：除了那一段，其他位元組完全相同
  const span = r.spans.get(JSON.stringify(['signal', 0, 'wave']));
  assert.strictEqual(out.text.slice(0, span[0]), SRC.slice(0, span[0]),
    '目標區間之前的位元組必須完全不變');
  assert.strictEqual(out.text.slice(out.text.length - (SRC.length - span[1])),
    SRC.slice(span[1]),
    '目標區間之後的位元組必須完全不變');
}

// 多筆編輯（由後往前套，才不會讓前面的區間位移）
{
  const r = C.parseSource(SRC);
  const out = C.patchSource(SRC, r, [
    { path: ['signal', 0, 'wave'], value: '0101010' },
    { path: ['signal', 1, 'name'], value: 'DATA' },
  ]);
  assert.strictEqual(out.ok, true);
  assert.ok(out.text.includes('wave: "0101010"'));
  assert.ok(out.text.includes("name: 'DATA'"), '第二筆必須沿用它自己的單引號風格');
  assert.ok(out.text.includes('// 主時脈'), '註解仍在');
}

// 結構性改變（新增一個 lane）無法只做局部替換 → 誠實回報
{
  const r = C.parseSource(SRC);
  const out = C.patchSource(SRC, r, [
    { path: ['signal', 2], value: { name: 'new', wave: '01' } },
  ]);
  assert.strictEqual(out.ok, false,
    '插入新元素不是局部替換，必須誠實回報而不是靜默重寫');
  assert.ok(out.rewroteRange, '必須說明它想動哪一段');
}
```

- [ ] **Step 2: 跑測試確認它紅**

- [ ] **Step 3: 實作**

`patchSource()`：

1. 每一筆 edit 用 `path` 去 `spans` 找區間；找不到 → `ok: false`
2. **由後往前**（區間起點遞減）套用替換，前面的區間才不會位移
3. 新值序列化時**沿用原區間的引號風格**：讀原本那段第一個字元是 `"` 還是 `'`
4. 值的型別若與原值不同（字串 → 陣列之類），視為結構性改變 → `ok: false`

- [ ] **Step 4: 跑測試確認它綠**

- [ ] **Step 5: Commit**

```bash
git add lib/editor/wave-codec.js test/wave-codec.test.js
git commit -m "feat(wave): write back a minimal patch, not a re-serialization

Editing one cycle rewrites exactly the bytes of that one string literal.
The comment two columns to its right, the file's indentation, and whichever
quote character that value happened to use all survive because they are
never touched. Edits apply back-to-front so earlier spans do not shift.

A change that is not a local replacement — inserting a lane, changing a
value's type — is refused rather than silently rewritten, and says which
range it wanted."
```

## Task 3: 波形字元與文件 ops

**Files:**
- Modify: `lib/editor/wave-codec.js`
- Modify: `test/wave-codec.test.js`

**Interfaces:**
- Produces（全部是純函式，輸入輸出都是普通物件，**不可變**——回傳新的 doc，不改原本的）：
  - `expandWave(wave) -> string[]`——把 `.` 解析成它延續的那個字元
  - `collapseWave(chars) -> string`——重新引入 `.`
  - `setCell(doc, laneIndex, cycle, ch) -> doc`
  - `setCellRange(doc, laneIndex, from, to, ch) -> doc`
  - `insertCycles(doc, at, count) -> doc`
  - `deleteCycles(doc, at, count) -> doc`
  - `copyCycles(doc, at, count) -> { kind:'cycles', count, lanes:[{ chars, data }] }`
  - `pasteCycles(doc, at, clip, mode) -> doc`（`mode` 是 `'insert'` 或 `'overwrite'`）
  - `addLane(doc, at, lane) -> doc` / `removeLane(doc, at) -> doc` / `moveLane(doc, from, to) -> doc` / `renameLane(doc, at, name) -> doc`

- [ ] **Step 1: 寫會紅的測試**

```js
// wave 字元
assert.deepStrictEqual(C.expandWave('p...'), ['p', 'p', 'p', 'p'],
  '. 延續前一個字元');
assert.deepStrictEqual(C.expandWave('01.x'), ['0', '1', '1', 'x']);
assert.strictEqual(C.collapseWave(['p', 'p', 'p', 'p']), 'p...',
  'collapse 必須重新引入 .');

// 往返一致：所有合法字元
{
  const LEVELS = '01xzpnhlud=23456789'.split('');
  for (const ch of LEVELS) {
    const w = ch + '..' + ch;
    assert.strictEqual(C.collapseWave(C.expandWave(w)), w,
      '往返必須一致：' + JSON.stringify(w));
  }
}

// setCell 不可變
{
  const doc = { signal: [{ name: 'a', wave: '0000' }] };
  const next = C.setCell(doc, 0, 2, '1');
  assert.strictEqual(next.signal[0].wave, '001.'.slice(0, 4).replace('.', '0'),
    'setCell 之後 collapse 的結果'); // 見下方註
  assert.strictEqual(doc.signal[0].wave, '0000', '原本的 doc 不得被改到');
}

// insert / delete cycles 對每一條 lane 都要作用
{
  const doc = { signal: [{ name: 'a', wave: '0011' }, { name: 'b', wave: 'xxyy' }] };
  const ins = C.insertCycles(doc, 2, 1);
  assert.strictEqual(C.expandWave(ins.signal[0].wave).length, 5);
  assert.strictEqual(C.expandWave(ins.signal[1].wave).length, 5,
    '插入 cycle 必須對每一條 lane 同時作用，否則波形會錯位');
}

// copy / paste
{
  const doc = { signal: [{ name: 'a', wave: '0101' }] };
  const clip = C.copyCycles(doc, 1, 2);
  assert.strictEqual(clip.count, 2);
  const pasted = C.pasteCycles(doc, 3, clip, 'insert');
  assert.strictEqual(C.expandWave(pasted.signal[0].wave).length, 6);
}

// lane ops
{
  const doc = { signal: [{ name: 'a', wave: '01' }, { name: 'b', wave: '10' }] };
  assert.strictEqual(C.moveLane(doc, 0, 1).signal[0].name, 'b');
  assert.strictEqual(C.removeLane(doc, 0).signal.length, 1);
  assert.strictEqual(C.renameLane(doc, 1, 'B').signal[1].name, 'B');
  assert.strictEqual(doc.signal[0].name, 'a', '原本的 doc 不得被改到');
}
```

**Files:**

- [ ] **Step 1: 寫會紅的測試**

```js
const assert = require('assert');
const G = require('../lib/editor/wave-geometry.js');

const doc = { signal: [{ name: 'clk', wave: '0101' }, { name: 'd', wave: 'xx01' }] };
const L = G.layoutOf(doc, { laneHeight: 40, cycleWidth: 20, nameColWidth: 60 });

assert.strictEqual(L.lanes.length, 2);
assert.strictEqual(L.width, 60 + 4 * 20, '寬 = 名稱欄 + cycle 數 × cycle 寬');
assert.strictEqual(L.height, 2 * 40);

// 往返：每一格的中心點必須 hit 回同一格
for (let lane = 0; lane < 2; lane++) {
  for (let cyc = 0; cyc < 4; cyc++) {
    const r = G.cellRect(L, lane, cyc);
    const hit = G.cellAt(L, r.x + r.width / 2, r.y + r.height / 2);
    assert.deepStrictEqual(hit, { laneIndex: lane, cycle: cyc },
      '中心點必須 hit 回同一格：lane=' + lane + ' cycle=' + cyc);
  }
}

// 名稱欄不是格子
assert.strictEqual(G.cellAt(L, 10, 20), null, '名稱欄不得回傳格子');
// 超出範圍
assert.strictEqual(G.cellAt(L, L.width + 5, 20), null);
assert.strictEqual(G.cellAt(L, 70, L.height + 5), null);

// 邊界：格子的左緣屬於自己，右緣屬於下一格
{
  const r = G.cellRect(L, 0, 1);
  assert.deepStrictEqual(G.cellAt(L, r.x, r.y + 1), { laneIndex: 0, cycle: 1 },
    '左緣屬於自己');
  assert.deepStrictEqual(G.cellAt(L, r.x + r.width, r.y + 1),
    { laneIndex: 0, cycle: 2 }, '右緣屬於下一格');
}

console.log('wave-geometry.test.js OK');
```

  s.undo();
  assert.strictEqual(s.isDirty(), false, 'undo 回到原點就不再是髒的');
  s.redo();
  assert.strictEqual(s.isDirty(), true);

  const patch = s.toPatch();
  assert.strictEqual(patch.ok, true);
  assert.ok(patch.text.includes('// 主時脈'), '註解必須存活到 patch 產出');
